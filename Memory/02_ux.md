## Flutter Mobile App

### Navigation Structure

GoRouter declarative routing. Bottom navigation bar with **5 tabs** (Dashboard, Map, Forecast, Alerts, Federated).

**DEC-011 (canonical):** `/citizen` is a GoRouter sub-route of `/` that renders as a `ModalBottomSheet`. It is NOT a 6th tab. The FAB on Dashboard calls `context.go('/citizen')` which GoRouter resolves to `showModalBottomSheet`. Tapping the back button or dragging down pops back to `/`. The bottom nav bar remains at 5 tabs at all times and does not change when the modal is open.

GoRouter route tree:
```dart
GoRoute(
  path: '/',
  builder: (context, state) => DashboardScreen(),
  routes: [
    GoRoute(
      path: 'citizen',
      pageBuilder: (context, state) => ModalPage(
        builder: (context) => CitizenUploadSheet(),
      ),
    ),
  ],
),
GoRoute(path: '/map', builder: (_, __) => MapScreen()),
GoRoute(path: '/forecast', builder: (_, __) => ForecastScreen()),
GoRoute(path: '/alerts', builder: (_, __) => AlertsScreen()),
GoRoute(path: '/federated', builder: (_, __) => FederatedScreen()),
```

All routes: / /citizen (modal) /map /forecast /alerts /federated

### Screen 1: Dashboard (/)

Purpose: Live AQI for user location + corridor summary.

Layout:
- Top bar: "PRANA" wordmark + notification bell icon
- Hero card (glassmorphism): Lottie animated radial AQI gauge for nearest station; large aqi_index value; category label colored per scale; station name + last-updated timestamp
- Fire count row: fire emoji + "247 active fires in Punjab today" + trend arrow vs yesterday
- Mini-map thumbnail (250px height): tap to open /map; shows fire dots only
- 3-hour sparkline chart (fl_chart LineChart): rolling aqi_index for user location
- FAB (bottom-right, accent-fire): camera icon -> context.go('/citizen')

States:
- Loading: shimmer skeleton on all cards
- Error (API unreachable): grey card with "Last updated [timestamp]"; retry button
- No location permission: prompt card; fallback to Delhi NCR default

### Screen 2: Map (/map)

Purpose: Full-screen MapLibre map with all data layers.

MapLibre layers (toggleable via bottom sheet toggle chips):
1. HeatmapStyleLayer "aqi_heatmap": source = /api/v1/aqi/surface GeoJSON; color interpolation per AQI scale; intensity weight = pm25_estimate property
2. CircleLayer "fire_hotspots": source = /api/v1/hotspots GeoJSON; orange pulsing circles; radius proportional to frp property
3. FillLayer "trajectory_24h": source = /api/v1/forecast/plume (t+24h polygon); semi-transparent orange fill; opacity 0.3
4. FillLayer "trajectory_48h": t+48h polygon; opacity 0.2
5. FillLayer "trajectory_72h": t+72h polygon; opacity 0.1
6. SymbolLayer "wind_arrows": wind direction arrows at 0.5-deg grid from Open-Meteo

Bottom sheet (draggable):
- Toggle chips: AQI Heatmap | Fire Hotspots | Trajectory | Wind
- Active fire count badge
- Tap on fire dot: bottom card shows frp, brightness, confidence, acq_datetime, distance to Delhi

States:
- Map loading: MapLibre default grey tiles until style loads
- Layer loading: individual toggle shows CircularProgressIndicator
- Offline: last cached GeoJSON displayed; banner "Offline mode - data as of [timestamp]"

### Screen 3: Forecast (/forecast)

Purpose: 72h fire-to-plume trajectory forecast.

Layout:

Purpose: Real-time incident ticker and multilingual advisories.

Layout:
- Live ticker (StreamProvider on WebSocket /ws/ncr): new alerts animate in from top
- Alert card fields: severity badge (Emergency/Warning/Watch colored), location, pollutant, satellite_ts, authority

States:

- Empty: "No active alerts for this corridor"
- WebSocket disconnected: grey banner "Reconnecting..."; falls back to polling /api/v1/aqi/stations every 60s

### Screen 5: Federated Learning (/federated)

Purpose: Demonstrate FL privacy-preserving architecture.

Layout:
- Title: "Federated Intelligence — No Raw Data Crosses State Borders"
- Animated node diagram (CustomPainter + AnimationController):
  - Left node: Punjab (wheat icon, green border)
  - Right node: Delhi (skyline icon, blue border)
  - Centre: Aggregator (shield icon)
  - Animated dashed lines: weight packets travel Punjab->Aggregator->Delhi->Aggregator loop
  - Round counter badge on Aggregator node
- "Start / Replay Training" button: streams cached fl_rounds metrics round by round
- Accuracy chart (fl_chart LineChart): 3 series — Punjab local, Delhi local, Global federated; global overtakes both by round 5-7
- Privacy badge row: "Raw PM2.5 readings stay in Punjab" | "Raw met data stays in Delhi" | "Only weight tensors shared"

States:
- Idle: node diagram static; "Press Start Training to begin"

- Complete: all 3 accuracy lines shown; global model highlight

### Screen 6: Citizen Upload (/citizen — ModalBottomSheet)

Purpose: Submit sky photo for PM2.5 estimation.

Rendered as: ModalBottomSheet with drag handle. NOT a full-screen route. See DEC-011.

Layout:
- Title: "Estimate Air Quality From Your Sky"
- Camera / Gallery toggle buttons -> image_picker
- Selected image preview (full width, rounded corners)
- "Analyse" button (accent-fire, disabled until image selected)
- Result card (after response): pm25_estimate value; confidence badge; aqi_category color chip; "Contributing to community data" message
- Opt-in location toggle: "Include my location in community data?"

States:
- No image: instructional placeholder illustration
- Uploading: CircularProgressIndicator; "Analysing haze levels..."
- Success: result card animates in
- Error: "Analysis failed — try a clearer sky photo"; retry button

## Notification Behavior (REQ-015)

Two distinct mechanisms. Both are required.

### Foreground (app visible)

Flow: WebSocket /ws/ncr receives alert message of type "alert" -> AlertsProvider (StreamProvider) emits new alert -> AlertsScreen ticker updates -> in-app SnackBar/banner rendered. No OS notification fired when app is in foreground.

### Background / Killed (app not visible)

Flow:
1. App launch: request notification permission (Android 13+ / iOS) via permission_handler.
2. background_fetch registers 15-minute periodic background task (minimum interval; OS may defer).
3. Background task calls GET /api/v1/alerts/latest with last_seen_id stored in SharedPreferences.
4. If response contains incident_id != last_seen_id: update last_seen_id in SharedPreferences; call flutter_local_notifications.show() with title, body, payload.
5. User taps notification: app opens to /alerts route.

Notification payload schema:
```json
{
  "id": "INC-20251104-001",
  "title": "Air Quality Emergency — Delhi NCR",
  "body": "AQI 387 at Anand Vihar. 312 fires detected in Punjab.",
  "severity": "emergency",
  "deep_link": "/alerts"
}
```

Permission handling:
- If denied: background_fetch runs but flutter_local_notifications.show() is skipped; in-app banner used in foreground instead.
- No notification sent without permission grant.
